# 999 SDD 阶段启动器 — 产品规格（PRD）

| 项 | 值 |
|---|---|
| Feature | 999-sdd-stage-launcher |
| Profile | standard |
| 状态 | draft → 已随实现验收 |
| 关联 | [BRIEF](../BRIEF.md) · [技术方案](../design/TECH_DESIGN.md) · [测试计划](../test/TEST_PLAN.md) |

## 1. 问题与目标

使用 my-ai-infra 做 SDD 时，阶段、对应 Skill 和提示词写在 `mai-specs/` 与 Skill 文档里，开发者每次都要离开会话去查「下一步该用哪个 Skill、提示词怎么写」。DSH 的输入框因此反复被打断。

目标：在 DSH Web 会话输入框下方提供一条常驻的阶段栏，一次点击即可把当前阶段的提示词填进输入框，按 Enter 就能发起该阶段任务。

非目标（本次不做）：

- 不解析 `mai-specs/` 自动识别当前 Feature 与阶段进度。
- 不自动执行 Skill、不代替用户发送消息。
- 不提供阶段产物预览、验收看板或 Feature 导航。
- 不新增 Host 服务、工具或持久化配置。

## 2. 用户故事

| ID | 故事 | 价值 |
|---|---|---|
| US1 | 作为正在推进 Feature 的开发者，我想在输入框旁看到完整阶段清单，以免回忆流程顺序。 | 减少上下文切换 |
| US2 | 作为开发者，我点一个阶段就想拿到可直接发送的提示词，而不是自己拼 Skill 名和参数。 | 降低启动成本 |
| US3 | 作为开发者，我希望提示词进入当前会话的输入框，发送前还能补充 Feature 编号或范围。 | 保留人工确认 |
| US4 | 作为插件使用者，我希望在输入框不可用（如没有会话）时仍有明确反馈，而不是静默失败。 | 可诊断 |

## 3. 业务流程

1. 用户打开任意会话，输入框下方常驻「SDD 阶段」栏，列出 8 个阶段：需求、产品规格、技术方案、方案评审、测试计划、编码实现、代码评审、验收。
2. 用户点击某阶段。
3. 插件把该阶段提示词写入当前会话输入框（`inputActions.setDraft`），并在栏内提示「已填入…，按 Enter 发送」。
4. 用户按 Enter 发送；Agent 按提示词调用对应 Skill。
5. 若当前输入框不可用（无会话或接口缺失），插件回退为「在当前工作区新建会话并填入提示词」；仍失败时在栏内显示错误原因。

## 4. 交互与文案

- 栏标题：`SDD 阶段`；提示：`点击阶段会把该阶段的提示词填入当前输入框，确认后发送即可。`
- 阶段按钮使用胶囊样式，`title` 属性给出完整提示词，便于悬停确认。
- 状态文案：
  - 成功：`已填入「<阶段>」提示词，按 Enter 发送`
  - 回退成功：`已为「<阶段>」新建会话并填入提示词`
  - 失败：`无法启动阶段：<原因>`
- 失败状态使用 `role="alert"`，成功使用 `role="status"`。

## 5. 验收条件

| ID | 条件 | 判定方式 |
|---|---|---|
| AC1 | 插件安装后，任意会话输入框下方出现「SDD 阶段」栏，含 8 个阶段按钮。 | 插件安装结果 + Slot 占用记录 + 人工目视 |
| AC2 | 点击阶段后，当前输入框内容变为该阶段提示词，且提示词包含 `my-<skill>` 调用名。 | 人工操作 + 输入框内容核对 |
| AC3 | 成功提示文案出现，且不影响后续手工编辑与发送。 | 人工操作 |
| AC4 | 无会话或 `inputActions` 缺失时，回退到新建会话并填入提示词；失败时显示错误文案。 | 代码路径核对 + 人工触发 |
| AC5 | 插件安装后不改变 DSH 既有输入框、通知和其他插件的渲染。 | 目视对比 + Slot 占用列表 |
| AC6 | `pnpm dsh web` 启动的同一页面刷新后插件仍在，状态栏不残留错误。 | 刷新页面 + 再查询 Slot |

## 6. 约束

- 只使用 DSH 已公开的 Client 扩展点：`slots.inject` / `slots.register`、`inputActions.setDraft`、`uiWorkspace.startSession`。
- 不修改 `packages/` 下任何 Host/Client 包，不以私有接口读取会话状态。
- 界面继承宿主主题变量，无硬编码主题色；插件不引入构建步骤与运行时依赖。
